## Notes

- The meeting is being recorded.  Our code of conduct applies to this meeting.  https://github.com/Ecma-TC54/tg2/blob/main/CODE_OF_CONDUCT.md.
- Intro by Michael, preliminary matters, proposed agenda.
- Minutes from last meeting: approved.
- Summary
  - **Specification Updates and Drafting**
  - Michael and John are structuring the ECMA-427 pull requests to align with the PURL 2nd Edition specifications.
  - The team confirmed the new ABNF grammar section will be represented as a text block extracted from the markdown.
  - The publication target for PURL 2nd Edition and VERS 1st Edition is December after approval by Ecma GA.
  - **Qualifier Standardization**
  - Michael proposed simplifying vcs_url qualifier documentation by summarizing existing SPDX standards to reduce verbosity.
  - Steve and Michael agreed to maintain the vcs_url qualifier as an informative guide rather than a strict standard.
  - The group decided to exclude "arch" qualifiers from the current draft to avoid rushing standardization, allowing for future inclusion.
  - **Future Standard Proposals**
  - Michael mentioned a potential new standard for advisory and vulnerability curation artifacts.
  - Michael recommended creating a new Task Group for this standard to ensure domain separation from current projects.
  - **Repository and Documentation Governance**
  - Steve granted the team maintainer permissions on the ECMA-427 and ECMA-xxx-VERS repositories to facilitate PR management.
  - The team agreed to use the PURL specification repository as the primary documentation source until official ratification.
  - Documentation will transition to the TC54 website following the expected ratification in December.
  - **Roadmap for Test Cases and Metadata**
  - Michael highlighted the requirement for a major restructuring of test cases to support new terminology and qualification logic.
  - The team plans to develop detailed issue templates for collecting metadata for VERS types not supported by the current schema.
- **Meeting Opening and Agenda Proposal**: Michael Herzog opened the TC54-TG2 meeting under ECMA rules of conduct. Michael proposed three agenda topics: the status of the VERS 1st Edition and PURL 2nd Edition, implementation changes protocols, and agenda additions from John Horan or Steve Springett. John and Steve had no additional topics to raise.
- **PURL Draft Review and Status Update**: Michael Herzog provided an update on PURL status, noting that sub-issues for the Recommended Qualifiers annex were reviewed, though GitHub access issues prevented them from closing some items. Michael Herzog outlined their planned pull requests for the ECMA-427 repository, structured by subsections and annexes, along with a written summary. Steve Springett confirmed his understanding of the plan for them to submit markdown files as pull requests to the ECMA-xxx-VERS repository.
- **ABNF Grammar Implementation**: Steve Springett inquired whether the ABNF grammar should be visualized or kept as a text block. John Horan noted that the grammar would be extracted from the embedded ABNF in the markdown. Michael Herzog explained that the layout would match Annex A with introductory text, a code block of roughly 100 lines, and closing text, while noting that lenient grammar remains outside the project scope.
- **Recommended Qualifiers and VCS URL Qualifier**: Michael Herzog presented the informative draft on Recommended Qualifiers, noting pending feedback requested from Philipe Ombredanne. Michael Herzog detailed updates to individual qualifiers, including percent-encoded URLs, download use cases, and repository URLs. Regarding the VCS URL qualifier, Michael Herzog proposed replacing the verbose and ancient SPDX references with a simplified summary while retaining PIP syntax and subpath and file name concepts. Steve Springett agreed with the simplified approach after noting that SPDX references lacked context, and Michael Herzog committed to removing stray SPDX mentions and single quotes.
-  **Architecture Qualifiers and Release Planning**: Michael Herzog discussed evaluating architecture qualifiers across approximately 40 type definitions, ultimately deciding to leave them off the current update because values vary and lack a strict global standard. Michael stated that individual communities already understand their architecture format (for an arch qualifier key), and leaving it off avoids rushing an incomplete specification. Michael Herzog noted that release 1.2.0 of VERS was published to match VERS output (https://github.com/package-url/vers-spec/releases/tag/v1.2.0).
- **EU Proposal for Vulnerability Curation**: Michael Herzog reported working with Philipe Ombredanne, Adam Herzog, and others on a major EU grant proposal named RATATOSSK, which outlines a potential three-year project timeline for a new TC54 standard focused on advisory curation and vulnerability curation artifacts. Michael Herzog proposed creating a separate task group for the new standard rather than nesting it under Task Group 2, noting that each standard should ideally have its own task group. Steve Springett and Michael Herzog discussed the structural symmetry of PURL and VERS as an exception to the single-standard task group rule.
- **Website Documentation and Versioning Strategy**: Michael Herzog raised questions regarding how to represent evolutionary VERS changes on the website prior to official ECMA publication in December. Steve Springett advised referring people to the purl-spec repository until December, after which the TC54 website will host the ratified version. Michael Herzog and Steve Springett agreed to freeze the ECMA-427 changes with a release point and proceed with implementation, noting that general assembly rejections of TC54 votes are extremely rare.
- **Test Cases and Future Priorities**: Michael Herzog outlined upcoming priorities, identifying the software advisory registry as the primary focus and a major restructuring of test cases as the close second. Michael detailed planned test case enhancements, including incorporating required and recommended framing, expected failure messages, and warning messages. Michael also noted plans to update Clause 5 language from shall to should to align with the new test cases.
- **GitHub Permissions and Final Review Schedule**: Steve Springett announced that Michael Herzog and John Horan were invited to the Task Group 2 conveners team on GitHub, granting them maintenance permissions on the ECMA-xxx-VERS and ECMA-427 repositories. Steve Springett confirmed plans to review the documentation with fresh eyes and post it for TC54 review over the upcoming week, covering PURL, VERS, and TEA (Transparency Exchange API). Michael Herzog and Steve Springett discussed schema collection plans for VERS type definitions using detailed issue templates for future editions.
- The meeting was adjourned.
