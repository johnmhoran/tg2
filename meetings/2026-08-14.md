- Summary
  - Michael Herzog provided status for the VERS specification project and plans for the 1st edition VERS standard submission to Ecma.
  - Steve Springett advised focusing on markdown format for the VERS standard for later conversion to ecmarkup format.
  - The group agreed that the focus for the VERS standard 1st edition should remain on canonical form.
  - Michael Herzog provided status for the PURL specification project and plans for the EMCA-427 2nd edition standard submission to Ecma.
  - The group discussed adding registered values for namespace and qualifiers keys to the PURL type schema.
  - The group agreed to document standard PURL qualifier keys in an informative annex to ECMA-427 2nd edition.
  - The group agreed that the current focus for the PURL ABNF grammar should represent canonical form and that it should be added to ECMA-427 within an annex.
  - The group agreed to schedule an extra TG2 meeting for Friday August 21 to review the status of PURL and VERS standards changes for Ecma.
- **Meeting Opening and Administrative Review**: Philippe Ombredanne opened the meeting of TC54 task group two by referencing the ECMA and TC54 codes of conduct. The group reviewed the previous meeting's minutes without objection, noting that participants could submit pull requests if corrections were needed.
- **Agenda Setting and ABNF Grammar Update**: Michael Herzog proposed focusing the meeting on VERS and PURL ECMA topics given time constraints. Jan Kowalleck provided a brief update regarding their active work on the ABNF grammar implementation, noting they would bring further discussion to future meetings.
- **Ecosystem Announcements**: Philippe Ombredanne highlighted new proposals for adopting PURL within the Fedora metadata system and the Conda enhancement proposal. Michael Herzog clarified that the Conda proposal involves making the namespace optional.
- **VERS Project Status**: Michael Herzog provided a status report on the VERS specification, noting that they are using projects to track issues and milestones to track pull requests. The current gating item is the review of the VERS JSON Schema, which Philippe Ombredanne stated would be completed shortly.
- **VERS Specification Documentation Process**: Michael Herzog discussed the drafting of the introduction, clause 5, and the VERS type definition schema. The group discussed the mechanics of creating the specification.html file, and Steve Springett advised focusing on content in Markdown first, after which they would transition the work to ecmarkup. The goal is to have the master file ready by early next week, after which the group will manage changes via pull requests.
- **VERS Test Cases and Canonical Form**: Michael Herzog confirmed that VERS follows a canonical form, and while they maintain recommended test cases to assist with normalization, normalization is not mandatory in the specification. The group agreed to prioritize creating VERS  type definitions that match existing PURL types as a test of the schema.
- **PURL Specification Milestone**: Michael Herzog reviewed the status of the PURL specification repo and the ECMA-427 2nd Edition milestone, noting it currently contains a limited number of items, including corrections to "shall" versus "should" terminology.
- **Standardizing Namespaces and Qualifiers**: The group discussed adding registered values for namespaces and qualifiers to the PURL type definitions, which would not be required for canonical form but would provide standardized messages for when a namespace is not registered.
- **Handling Granular Technical Changes**: Jan Kowalleck requested guidance on whether to create tickets or pull requests for granular issues like defining path segments. Michael Herzog advised that for detailed technical fixes, a pull request is sufficient, but if the change impacts the core specification wording, a ticket should be created for higher visibility.
- **Standard Qualifier Keys Documentation**: Michael Herzog and the group discussed how to document standard qualifier keys. Philippe Ombredanne suggested documenting these in an informative annex for the current edition, with the intention of making it normative in the next edition, to avoid excessive process constraints.
- **ABNF Grammar Placement**: Regarding the ABNF grammar, the group agreed that it should represent the canonical form only and be placed in an annex. The group agreed to exclude the "how to parse" documentation from the current annex to maintain focus.
- **Normalization and Case Sensitivity**: The group discussed normalization rules for PURL types like pypi and ALPM. While acknowledging that some package ecosystems have historical issues with case sensitivity, the participants agreed that "shall" remains the appropriate term for mandatory normalization rules to prevent confusion, despite some ecosystem inconsistencies.
- **PURL Locatability**: The group addressed the concept of whether a PURL is locatable, noting that while this is a challenging issue in some ecosystems, they agreed not to address it in the current scope as it is a long-term problem.
- **Follow-up Meeting Scheduling**: Michael Herzog proposed a follow-up meeting in one week to maintain progress on the project timeline, which the group accepted. Philippe Ombredanne reminded them to announce the meeting on the relevant channels.
- **Closing and Final Schema Adjustments**: In closing, Philippe Ombredanne and Michael Herzog coordinated final updates to the VERS type JSON Schema, with Philippe Ombredanne agreeing to push necessary updates to the pull request.
- The meeting was adjourned.
